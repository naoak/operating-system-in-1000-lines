# WebAssembly 向けの移植

RISC-V 版を基に、Wasm を実行環境として作り直した版です。
C で書いたカーネルとシェルを、それぞれ `kernel.wasm` と `shell.wasm` にコンパイルします。
プロセス管理、スケジューラ、システムコール、ファイルシステムはカーネルが実装します。

## ビルドと起動

Wasm バックエンドと `wasm-ld` を持つ Clang、tar、Python 3 が必要です。
[wasi-sdk](https://github.com/WebAssembly/wasi-sdk/releases) の Clang も使えます。
WASI のランタイムやライブラリには依存しません。

```sh
WASI_SDK_PATH=/path/to/wasi-sdk ./wasm/build.sh
# または WASM_CC=/path/to/clang ./wasm/build.sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory wasm
```

ブラウザで <http://localhost:8000/> を開きます。
`file://` で HTML を直接開くのではなく、HTTP サーバーを使ってください。

`hello`、`readfile`、`writefile`、`help`、`exit` を実装しています。
`writefile` の後に `readfile` を実行すると変更を確認できます。
ディスクの変更は実行中のメモリに保存します。再起動前に **Download disk** で
tar ファイルとして取り出せます。再起動はビルド時のイメージから始まります。

Node.js 18 以降があれば、ブラウザと同じ Wasm モジュールとホスト実装をテストできます。

```sh
WASI_SDK_PATH=/path/to/wasi-sdk ./wasm/build.sh --test
```

## RISC-V 版からの変更

| 元の実装 | Wasm 版 |
| --- | --- |
| SBI によるコンソール操作 | ホストにインポートした入出力関数 |
| `ecall` によるシステムコール | ユーザーモジュールがインポートする `os.syscall` |
| Sv32 のページテーブル | プロセスごとに共有しない linear memory |
| 物理ページの確保 | カーネルの `memory.grow` による 64 KiB 単位の確保 |
| レジスタとスタックの保存・復元 | `step()` が明示的に状態を保存して制御を返す方式 |
| VirtIO ブロックデバイス | カーネル内のディスクイメージ |
| tar ベースのファイルシステム | 同じ ustar 形式を読み書きする C の実装 |

`common.c` のメモリ操作・文字列操作・`printf` は共有します。
RISC-V 版のソースと起動方法はリポジトリ直下にあります。

## カーネルとプロセスの境界

ホストは `runtime.mjs` です。Wasm のロード、プロセスのインスタンス化、
メモリ間コピー、コンソールの接続を担当します。
ユーザープログラムには `os.syscall` だけを渡し、カーネルのメモリは渡しません。
PID はホストがインスタンスに結び付けます。

システムコールのポインタは呼び出し元のメモリ内のオフセットです。
ホストが名前の終端とバッファの範囲を確認し、カーネル専用のメッセージ領域に
コピーします。カーネルは現在実行中の PID、要求の種類、長さを確認して処理します。
ファイル読み出しの結果もコピーでユーザーメモリに返します。

スケジューラは C のカーネルにあり、実行可能なプロセスをラウンドロビンで選びます。
入力がないシェルは待機状態になり、ホストが入力を渡すと実行可能に戻ります。
ユーザープログラムの Wasm trap は、そのプロセスの異常終了として扱います。

ブラウザでは OS 全体を Web Worker 内で動かします。
UI は入力と出力のメッセージだけを扱います。

## この版の範囲

- wasm32 向けです。各モジュールのメモリは初期 256 KiB、上限 16 MiB です。
- プロセスは起動ごとに最大 8 個です。終了したスロットの再利用は未実装です。
- 協調スケジューリングです。`step()` が戻らないプログラムを強制的に中断する機能はありません。
  ブラウザの Restart は Worker 全体を終了して復旧します。
- シェルは入力処理を状態機械に書き換えています。任意の C プログラムをそのまま
  中断・再開する仕組みはありません。必要なら
  [Asyncify など](https://emscripten.org/docs/porting/asyncify.html)を別途検討します。
- ファイルは既存の 2 個、各 1024 バイトまで、ディスクは 32 KiB までです。
  ファイルの新規作成、ディレクトリ、ブラウザへの自動永続化は未実装です。

Wasm のメモリ、インポート、インスタンスのモデルは
[公式仕様](https://webassembly.github.io/spec/core/intro/overview.html)を参照してください。
